# 학습자료 생성 시스템 필수 개발 원칙

이 규칙은 학습자료 생성·프롬프트·검수·재생성·테스트를 수정하는 모든 AI와 개발자에게 적용된다.

프로젝트 지속 규칙으로 채택 (사용자 지시 2026-09-10). 학습자료 관련 모든 코드 변경은 착수 전 이 문서와 §10 반사실 테스트를 통과해야 한다.

---

## 1. 최우선 목표

목표는 발견된 오류를 하나씩 차단하는 것이 아니다.

사용자의 학년·과목·영역·단원·주제·자료유형에 맞는 생성 기준을 요청마다 동적으로 구성하고, 그 기준에 따라 처음부터 적합한 결과물을 생성하는 것이다.

**자동 재생성은 잘못 설계된 최초 생성을 보완하는 주된 방법이 아니라 마지막 안전망이다.**

## 2. 사례별 교정 금지

오류 사례를 발견했다는 이유로 다음을 추가하지 않는다.

- 특정 과목명에 대한 if/else
- 특정 단원명이나 주제명에 대한 분기
- 특정 단어·문장·자모·연산 이름을 검사하는 코드
- 발견된 오류를 막기 위한 금지어 목록
- 샘플 A·B만 통과시키는 프롬프트 예시
- 특정 정답이나 선택지를 알고 있는 테스트 코드
- 동일한 사례를 정규식으로 차단하는 검증기

예:
- `if subject === "MATH"`
- `if topic.includes("받아올림")`
- `forbiddenWords = ["음수", "모음"]`
- `if hint.includes(correctOption)`
- `if option === "가방"`

위와 같은 코드는 공통 생성·검수 경로에 추가하지 않는다.

## 3. 오류 발견 시 의무 분석 순서

오류가 발견되면 코드를 수정하기 전에 반드시 다음 순서로 원인을 분류한다.

1. GenerationContext에 필요한 정보가 빠졌는가?
2. LearningProfile의 교육 목표나 범위가 부족한가?
3. ContentPlan이 잘못 설계됐는가?
4. 생성 모델이 ContentPlan을 따르지 않았는가?
5. 의미 검수 모델이 계획과 결과의 불일치를 놓쳤는가?
6. 스키마·수량·계산처럼 코드로 확정 가능한 오류인가?

오류 사례 자체를 차단하는 수정안을 제출하지 않는다.

## 4. 생성 전에 계획한다

LearningDocument를 바로 생성하지 않는다.

먼저 다음 자료를 조합해 GenerationContext를 만든다.

- 사용자 입력
- 학년과 과목
- 영역과 단원
- 세부 주제
- 자료의 형과 수량
- 난이도와 배포 대상
- LearningProfile의 학습 목표
- 선수 학습
- 허용 범위와 제외 범위
- 어휘 수준
- 권장 문항·활동 유형
- 평가 기준

그다음 요청에 맞는 ContentPlan을 먼저 작성한다.

ContentPlan은 각 문항이나 활동에 대해 다음을 정의한다.

- 무엇을 학습하거나 평가하는가
- 학생이 어떤 사고나 행동을 해야 하는가
- 무엇을 근거로 정답 또는 성공을 판단하는가
- 어떤 형태의 오답 또는 어려움이 적절한가
- 힌트는 어떤 사고를 도와야 하는가
- 학년 수준에 적합한 이유
- 다른 문항과 구별되는 역할

문항은 이 ContentPlan을 구현하는 방식으로 생성한다.

## 5. 처음부터 잘 생성하기 위한 내부 점검

생성 모델은 최종 응답을 반환하기 전에 자체적으로 다음을 수행한다.

1. 모든 문항이 ContentPlan과 연결되는지 확인
2. 각 문항을 실제 학생처럼 풀어보기
3. 정답 또는 기대 결과가 판단 가능한지 확인
4. 오답과 힌트가 설계 의도에 맞는지 확인
5. 학습 목표·주제·학년 수준과 대조
6. 문제가 있으면 사용자에게 반환하기 전에 스스로 다시 생성
7. 점검을 통과한 최종본만 구조화된 결과로 반환

이 내부 점검은 특정 단어 검사 방식으로 구현하지 않는다.

## 6. 독립적인 의미 검수

최초 생성이 끝나면 별도의 검수 모델이 다음 세 자료를 비교한다.

- GenerationContext
- ContentPlan
- LearningDocument

검수 모델은 고정 정답이나 금지어를 검사하지 않고 다음을 의미적으로 판단한다.

- 학습 목표를 실제로 다루는가
- 단원과 세부 주제에 맞는가
- 학년 수준에 맞는가
- 학생이 문항 자체만으로 이해할 수 있는가
- 정답 또는 기대 결과의 근거가 명확한가
- 오답이 단순 오류가 아니라 교육적으로 타당한가
- 힌트가 사고를 돕고 답을 대신 하지 않는가
- 문항 간 역할과 경험이 충분히 구별되는가
- 선택한 자료의 형으로써 실제 사용 가능한가

검수 결과는 다음 구조로 반환한다.

```json
{
  "pass": true,
  "reason": "판정 요약",
  "failedItemIndexes": [],
  "items": []
}
```

실패한 경우:

```json
{
  "pass": false,
  "reason": "전체 판정 요약",
  "failedItemIndexes": [1],
  "items": [
    {
      "itemIndex": 1,
      "reason": "계획과 결과가 맞지 않는 의미적 이유",
      "repairInstruction": "학습 목표와 난이도를 유지한 재생성 지시"
    }
  ]
}
```

## 7. 부분 재생성

검수 실패 시 전체 문서를 다시 만들지 않는다.

- 실패한 item만 최대 1회 재생성
- 원래 GenerationContext 유지
- 원래 ContentPlan 유지
- 실패 이유와 repairInstruction만 추가 전달
- 재생성 후 동일한 의미 검수를 다시 실행
- 두 번째도 실패하면 결과를 숨기고 사용자에게 실패 안내
- 실패 시 기존 정책에 따라 크레딧 환불

재생성 과정에서 새로운 금지어나 조건문을 만들지 않는다.

## 8. 코드로 허용되는 검증

코드 검증은 도메인 지식과 무관하게 참·거짓을 확정할 수 있는 것만 허용한다.

허용:
- JSON·스키마 유효성
- 필수 필드
- 요청 수량과 결과 수량
- item ID 중복
- 정답 인덱스 범위
- 선택지 ID 중복
- 파일 생성 여부
- 배포 대상에 따른 정답 필드 제거
- 명시된 수식의 계산 결과
- 저장·다운로드 무결성

새 코드 검증기를 추가하려면 다음 질문을 모두 통과해야 한다.

1. 특정 과목명·단원명·주제명·단어가 없어도 작동하는가?
2. 처음 보는 교과서 예시 없이 적용되는가?
3. 의미 이해가 필요 없는 객관적 사실인가?
4. LearningProfile 데이터로 처리할 사항이 아닌가?
5. AI 의미 검수로 처리해야 할 판단이 아닌가?

하나라도 "아니오"이면 코드 검증기로 추가하지 않는다.

## 9. LearningProfile 원칙

LearningProfile은 금지어 사전이 아니다.

프로필에는 다음 교육 정보만 저장한다.

- 학습 목표
- 선수 학습
- 허용 학습 범위
- 제외 학습 범위
- 어휘와 문장 수준
- 권장 문항·활동 유형
- 평가 기준
- 교육과정 근거

새 과목·학년·단원을 지원할 때 생성 코드와 검수 코드를 수정하지 않는다. 프로필 데이터 추가만으로 같은 생성 흐름을 사용해야 한다.

## 10. 수정 제출 전 반사실 테스트

모든 수정안 제출 전에 다음 질문에 답한다.

**"현재 실패 사례의 과목명·단원명·주제명·단어를 전부 다른 미지의 교과로 바꾸어도 이 수정이 그대로 유효한가?"**

- 예: 공통 구조 개선으로 채택 가능
- 아니오: 사례별 하드코딩이므로 폐기
- 판단 불가: 구현하지 말고 구조를 다시 검토

## 11. 테스트 원칙

실패 사례는 회귀 fixture로 보존할 수 있지만, 테스트는 해당 사례의 답을 코드에 입력하지 않는다.

테스트 목적:
- 특정 단어를 차단하는가가 아님
- 프로필과 계획과 결과가 불일치할 때 의미 검수가 탐지하는가
- 정상적인 결과를 과도하게 거부하지 않는가
- 실패 item만 다시 생성되는가

## 12. AI의 응답 의무

사용자가 생성 오류를 제시했을 때 즉시 코드 수정이나 금지어 추가를 제안하지 않는다.

먼저 다음 형식으로 응답한다.

- 오류가 발생한 생성 단계
- 부족했던 도입 정보
- 최초 생성 품질의 난이도 구조적 원인
- 기존 프로필 또는 ContentPlan 보완 여부
- 특정 사례 적용 코드가 포함되지 않았다는 확인
- 처음 보는 과목에도 같은 구조가 작동하는지 확인

사용자가 명시적으로 요청하지 않는 한 개별 사례 적용 패치를 제안하지 않는다.
